0) SHARED END-TO-END FLOW (APPLIES TO Q1-Q9)
============================================================

A) Input and sample loading
1. Input QA rows come from V2V-GoT QA JSON (train/val split), typically:
   DMSTrack/V2V4Real/official_models/<split>/npy/co_llm/v2v4real_3d_grounding_qa_dataset_v2vgot.json
2. Adapter: V2VGoTQABenchmarkAdapter converts each row into BenchmarkSample.
3. Each sample includes:
   - sample_id, qa_type_id, task_type
   - scene seed (agents, asker id, trajectory context, raw record)
   - question text and reference answer text (for evaluation/training only)

B) Cooperative KG formation (scene preparation)
Pipeline stages (deterministic, in-memory dataclass graph):
1. ProcessedSceneEnricher: attach processed observations/tracks/visibility facts.
2. ObservationAssociator: match observations to tracks (type + distance gates).
3. TrackSupportEnricher: add observation support/provenance.
4. CandidateTrackCreator: promote unmatched observations to candidate tracks.
5. CandidateTrackResolver: keep plausible candidates, prune weak artifacts.
6. CrossAgentAssociator: associate same object evidence across agents.
7. CrossAgentSupportEnricher: add cross-agent support/provenance.
8. TrackMerger: conservative duplicate merging.
9. TrackQualityAssessor: compute confidence/support/conflict/uncertainty/status updates.
10. VisibilityReasoner: visible/occluded/uncertain facts for asker.
11. RelationBuilder: build relation edges (near trajectory, path relevant, spatial, cooperative support, low conflict).

Graph entities and facts:
- Nodes/entities: CooperativeScene, AgentContext, ObjectTrack, ObservationEvidence.
- Facts/edges: VisibilityFact, RelationFact, ProvenanceRecord.
- Key quality signals: support_count, conflict_score, uncertainty_score, confidence, status.

C) Router inference and task head dispatch
- Script path: scripts/run_qa_split_pipeline.py -> scripts/evaluate_qa_router.py
- Router: V2VGoTQARouter dispatches to task handlers by task type.
- Baseline mode for promoted runs: cooperative (ego_only used mainly for ablations).

D) Output formatting and official evaluation
1. Raw predictions JSONL from router include sample_id, qa_type_id, object_ids and/or answer_text.
2. Export script: scripts/export_qa_predictions.py converts to official-style outputs field.
   - Q1-Q4: object_id -> coordinate phrase rendering.
   - Q5/Q6/Q8/Q9: handler answer_text is passed through (deferred tasks).
3. Official evaluation path:
   scripts/evaluate_official_qa.py and run_v2vgot_official_qa_eval wrapper.
4. Metric conventions:
   - Q1-Q4: strict localization F1/P/R at 0.5m.
   - Q5/Q7: L2 (l2_error_avg_123_all primary).
   - Q6: binary accuracy.
   - Q8: normalized action error = action_edit_dist / 8.
   - Q9: trajectory L2 avg (l2_error_avg_all).

1) Q1 NOTABLE OBJECTS (qa_type_id=11)
============================================================
Question:
- Which notable objects are visible to the asking vehicle?

Objective:
- Return visible, trajectory-relevant objects while suppressing weak/noisy candidates.

Input:
- Cooperative KG scene with object tracks + visibility + trajectory + provenance.

KG logic used:
- Visibility filter: object must be visible to asker.
- Relevance signals: distance to trajectory / first waypoint, support/provenance, confidence, conflict/uncertainty penalties.
- Candidate status is penalized vs supported/confirmed tracks.

Features used for inferencing:
- No learned model in promoted checkpoint.
- Deterministic heuristic scoring over graph-native attributes:
  visibility, trajectory proximity, support_count, confidence, status, conflict_score, uncertainty_score, distance-to-asker.

Model/hyperparameters/loss:
- Model: deterministic heuristic ranker (notable_ranker=heuristic).
- No trainable loss/epochs.

Output format:
- Router returns selected object_ids.
- Export renders: "There is a car at (x,y) visible to you." (one phrase per selected object).

Final promoted result:
- Val F1/P/R: 0.585836 / 0.674759 / 0.517621
- Baseline ref: 0.525000
- Relative improvement: +11.59%

2) Q2 OCCLUDING OBJECTS (qa_type_id=12)
============================================================
Question:
- Which objects obstruct the asking vehicle's view?

Objective:
- Select true blocker objects causing occlusion, with controlled precision-recall tradeoff.

Input:
- Cooperative KG with visible objects + hidden/occluded objects + geometry/provenance.

KG logic used:
- Build blocker candidates from visible objects.
- Pair each visible blocker with hidden-object evidence via:
  - line-of-sight bearing alignment,
  - plausible depth ordering (hidden behind visible),
  - visible-hidden proximity,
  - hidden-object trajectory relevance.
- Add provenance/support and confidence terms.
- Penalize conflict/uncertainty/candidate-only quality.
- Sparse-evidence fallback backfills from visible pool when blocker evidence is thin.

Features used for inferencing:
- No learned model in promoted checkpoint.
- Deterministic risk-adaptive score built from KG geometry + support + quality features.

Model/hyperparameters/loss:
- Model: risk_adaptive deterministic selector.
- No trainable loss/epochs.

Output format:
- Router returns blocker object_ids.
- Export renders: "There is a car at (x,y) obstructing your view."

Final promoted result:
- Val F1/P/R: 0.427921 / 0.452542 / 0.405840
- Baseline ref: 0.301000
- Relative improvement: +42.17%

3) Q3 INVISIBLE OBJECTS (qa_type_id=13)
============================================================
Question:
- Which notable objects are invisible/occluded to the asking vehicle?

Objective:
- Maximize hidden-object recall without excessive false positives.

Input:
- Cooperative KG with visibility states and hidden-object candidates.

KG logic used:
- Stage 1 retrieval: broad hidden-candidate pool from occluded/uncertain objects.
- Stage 2 acceptance: learned acceptor filters broad candidate pool.
- Promoted retrieval knobs: shortlist_size=64, max_distance_to_trajectory=8.0m, max_results=1.

Features used for inferencing (candidate row features):
- rank, role_score,
- relative_x, relative_y, abs_relative_x, abs_relative_y,
- distance_to_asker, distance_to_trajectory,
- support_count,
- conflict_score,
- status one-hot (confirmed/supported/candidate).

Model/hyperparameters/loss:
- Selected policy: invisible-ranker=logreg_acceptor.
- Deployable model:
  outputs/phase8_train_dev/q3_policy_optimization_traj8_short64/
  q3_logreg_mlp_legacy_traj8_short64_logreg_max_recall_p0p5_t0p33_deployable.json
- Trainer: scripts/train_q3_invisible_acceptor.py
- Optimizer: custom batch logistic regression (manual gradient descent).
- Defaults in trainer: learning_rate=0.05, epochs=600, l2=0.01, class balancing on.
- Threshold search on train: 0.05..0.95, selected threshold=0.33 in promoted checkpoint.
- Loss form: weighted binary cross-entropy with L2 penalty.

Output format:
- Router selects max one object id.
- Export renders: "There is a car at (x,y) invisible to you."

Final promoted result:
- Val localization F1/P/R: 0.493934 / 0.488014 / 0.500000
- Baseline ref: 0.440000
- Relative improvement: +12.26%
